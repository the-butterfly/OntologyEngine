# 非结构化来源处理

> **status**: draft | **phase**: phase2 | **source_of_truth**: 本文档 | **last_verified**: 2026-05-25 | **[待扩展]**

---

## 目的

定义 OntologyEngine 处理非结构化知识来源的统一流程。结构化来源（数据库表、代码、API 响应）已有明确管线，本文档补全非结构化来源（PDF、图片、网页、泛文本）的摄入路径。

---

## 来源分类

| 类型 | 特征 | 典型场景 | 挑战 |
|------|------|---------|------|
| **PDF 文档** | 排版复杂、含表格/图表 | 年报、合同、制度文件 | 版面分析、表格还原 |
| **图片** | 视觉信息密集 | 流程图、截图、设计图 | VLM 理解、信息提取 |
| **网页** | 动态结构、DOM 树 | 新闻、文档站、API 文档 | 噪声过滤、内容提取 |
| **泛文本** | 无固定结构 | 对话记录、笔记、邮件 | 分块、意图识别 |

---

## 处理管线

### 统一入口

```
非结构化来源到达
    │
    ▼
[Stage -1] 格式预处理
    │
    ├─ PDF   → 版面分析 → 文本 + 表格 + 图片分离
    ├─ 图片  → VLM 描述 → 文本描述 + 结构化提取
    ├─ 网页  → DOM 解析 → 正文提取 + 去噪
    └─ 文本  → 直接传入 Stage 0
    │
    ▼
[Stage 0] 哈希校验（SHA256）
    ↓
[Stage 1] 智能分块（QMD 算法）
    ↓
[Stage 2] 两通道提取
    ↓
[Stage 3] 消歧与对齐
    ↓
[Stage 4] Schema 绑定与质量评分
    ↓
[Stage 5] 写入与索引
```

### Stage -1: 格式预处理（各类型专属）

#### PDF 处理

```
PDF 输入
    │
    ▼
1. 版面分析（Layout Parser）
   ├─ 文本区域 → 提取正文
   ├─ 表格区域 → 结构化还原（行/列/单元格）
   ├─ 图片区域 → 分离为独立图片 Fragment
   └─ 页眉页脚/页码 → 过滤
    │
    ▼
2. 文本清洗
   ├─ 连字符修复
   ├─ 段落重组（跨页断行合并）
   └─ 特殊字符清理
    │
    ▼
3. 元数据提取
   ├─ 标题/作者/日期（从文档属性或首）
   ├─ 目录结构（H1-H6 层级）
   └─ 引用/脚注链接
    │
    ▼
输出: (纯文本, 表格数据[], 图片列表[], 元数据{})
```

#### 图片处理

```
图片输入
    │
    ▼
1. VLM 描述生成
   ├─ 整体场景描述（1-2 句）
   ├─ 关键元素列表
   └─ 文字内容（OCR 提取）
    │
    ▼
2. 图片类型分类
   ├─ 流程图/架构图 → 提取节点和边 → Mermaid 代码块
   ├─ 表格截图 → OCR 表格还原 → CSV 格式
   ├─ 代码截图 → OCR 代码还原
   ├─ 界面截图 → UI 元素描述
   └─ 其他 → 通用描述
    │
    ▼
3. 结构化提取（仅对流程图/表格）
   ├─ 流程图 → 节点列表 + 边列表 → 结构化存储
   └─ 表格 → 行/列结构化 → EntityInstance 候选
    │
    ▼
输出: (描述文本, OCR文本, 类型标签, 结构化数据?)
```

#### 网页处理

```
URL / HTML 输入
    │
    ▼
1. 内容获取
   ├─ 静态 HTML → 直接解析
   ├─ 动态页面 → Playwright/Puppeteer 渲染
   └─ API 返回 JSON → 结构化处理
    │
    ▼
2. DOM 正文提取
   ├─ Readability 算法提取正文
   ├─ 导航/广告/侧边栏 → 过滤
   ├─ 代码块 → 保留语言标签
   └─ 图片 → 提取 alt 文本 + 保留 URL
    │
    ▼
3. 结构化信息提取
   ├─ Open Graph / JSON-LD 元数据
   ├─ 标题/作者/发布时间
   └─ 面包屑/分类标签
    │
    ▼
输出: (正文HTML, 纯文本, 元数据{}, 图片URL[])
```

#### 泛文本处理

```
文本输入
    │
    ▼
1. 格式检测
   ├─ Markdown → 保留标题/代码块/列表结构
   ├─ JSON/YAML → 结构化解析
   └─ 纯文本 → 段落检测
    │
    ▼
2. 意图分类（LLM 轻量判断）
   ├─ 知识陈述 → 正常进入提取
   ├─ 问题/查询 → 标记为 question 类型
   ├─ 指令/规则 → 标记为 rule 候选
   └─ 对话/讨论 → 标记为 discussion
    │
    ▼
输出: (纯文本, 格式标签, 意图标签)
```

## 分块策略（Stage 1 的扩展）

### 各类型分块参数

| 类型 | 目标大小 | 重叠 | 分块边界优先级 |
|------|---------|------|--------------|
| 文档正文 | 900 tokens | 15% | H1 > H2 > 段落 > 空行 |
| 表格 | 整个表 | 0% | 表格完整性优先 |
| 代码块 | 函数/类级别 | 5% | AST 边界 > 空行 |
| 图片描述 | 单图 | 0% | 不分块 |
| 网页正文 | 900 tokens | 15% | H1 > H2 > 段落 |
| 对话记录 | 5-10 轮对话 | 2 轮 | 话题转换边界 |

### Markdown 特殊处理

```
Markdown 输入
    │
    ▼
1. YAML frontmatter 分离
   └─ 元数据 → Fragment 的 metadata 字段
    │
    ▼
2. body-only 哈希（仅对正文内容计算 SHA256）
   └─ frontmatter 变更不使缓存失效
    │
    ▼
3. 代码围栏保护
   └─ 不在代码块内部切分，代码块作为整体或按函数切分
    │
    ▼
4. wikilink / 引用链接识别
   └─ [[entity_name]] → 预建立关系边候选
```

## Schema-Aware 提取（非结构化适配）

### 提取模板注入

对于 PDF/网页/图片等非结构化来源，LLM 提取时注入 Schema 提取模板：

```yaml
# 示例：从年报 PDF 中提取交易对手信息
extraction_prompt: |
  你是金融文档分析助手。请从以下年报文本中提取交易对手信息。
  
  需要提取的字段（参考 Schema）：
  - debt_ratio (decimal, required): 资产负债率
  - registered_capital (Money, required): 注册资本
  - risk_grade (enum: A/B/C/D, optional): 风险等级
  
  提取规则：
  1. 每个字段必须标注 confidence (0.0-1.0)
  2. 找不到字段时输出 null，不要猜测
  3. 数值字段必须带单位
```

### 置信度校准

| 来源类型 | 基础置信度 | 校准因子 |
|---------|----------|---------|
| 结构化数据（数据库/API） | 1.0 (EXTRACTED) | — |
| 代码 AST 提取 | 1.0 (EXTRACTED) | — |
| PDF 表格还原 | 0.8-0.9 | 表格清晰度 × 0.8 |
| 图片 VLM 描述 | 0.5-0.7 | VLM 模型质量 × 0.7 |
| 网页正文提取 | 0.6-0.8 | 正文提取质量 × 0.9 |
| 泛文本 LLM 提取 | 0.4-0.9 | 与 Schema 对齐度 × 0.5 |

## 存储策略

### KnowledgeFragment 元数据扩展

非结构化来源的 Fragment 需携带额外元数据：

```python
class UnstructuredMetadata:
    source_type: str          # pdf | image | webpage | plain_text
    original_format: str      # 原始格式标识
    preprocessing_result: dict # 预处理产出（OCR文本、VLM描述等）
    layout_info: dict | None  # 版面分析结果（PDF 专用）
    image_urls: list[str]     # 引用的图片 URL
    extraction_method: str    # vlm | ocr + llm | readability + llm
```

### 原文保留策略

```
Layer-R 存储原则：
  1. PDF → 存储提取的纯文本 + 原文 PDF 的存储路径（可选保留原文件）
  2. 图片 → 存储 VLM 描述文本 + 原始图片 URL/路径
  3. 网页 → 存储提取的纯文本 + 原始 URL + 抓取时间戳
  4. 泛文本 → 存储原始文本
```

## 增量处理

### 变更检测

| 类型 | 变更信号 | 处理方式 |
|------|---------|---------|
| PDF | 文件 SHA256 变更 | 重新预处理 + 提取 |
| 图片 | 文件 SHA256 变更 | 重新 VLM 描述 + 提取 |
| 网页 | URL 内容变更（定时抓取比对） | 重新 DOM 解析 + 提取 |
| 泛文本 | 文本 SHA256 变更 | 重新分块 + 提取 |

### 缓存策略

```
预处理缓存（Stage -1）:
  键: SHA256(原始内容)
  值: (预处理产出, 分块结果)
  命中: 跳过 Stage -1 和 Stage 0-1

提取缓存（Stage 2）:
  键: SHA256(分块内容) + extraction_method
  值: LLM 提取结果
  命中: 跳过 Stage 2 LLM 调用
```

## 与结构化来源的差异

| 维度 | 结构化来源 | 非结构化来源 |
|------|----------|-------------|
| 预处理 | 无需（字段已结构化） | 需要（格式转换 + 版面分析） |
| 分块 | 行/函数级确定性分块 | 启发式分块 + QMD |
| 提取 | AST 确定性提取为主 | LLM 语义提取为主 |
| 置信度 | 高（EXTRACTED = 1.0） | 中（INFERRED = 0.4-0.9） |
| 增量 | 精确字段级变更检测 | 文件级 SHA256 变更检测 |
| 溯源 | 精确到字段 | 精确到段落/区域 |
