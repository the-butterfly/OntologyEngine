# 项目目标

## 阶段目标

### Phase 0: MVP (当前)
**Deadline**: 2026-04-30

| 目标 | 验收标准 |
|------|----------|
| Schema 可定义 | KGML YAML 解析通过 |
| 规则可执行 | 供应链金融5条规则跑通 |
| Demo 可演示 | 单脚本运行完整流程 |

### Phase 1: 可用 (4周)
**Deadline**: 2026-05-31

| 目标 | 验收标准 |
|------|----------|
| 查询高性能 | DuckDB 百万级节点 P99 < 200ms |
| 规则热更新 | YAML 修改后秒级生效 |
| 向量检索 | Faiss 集成，混合查询可用 |

### Phase 2: 好用 (4周)
**Deadline**: 2026-06-30

| 目标 | 验收标准 |
|------|----------|
| Agent 集成 | MCP 协议支持，Claude 可调 |
| 可视化 | Schema/规则/结果的 Web UI |
| 多场景 | 3个垂直领域 Schema |

### Phase 3: 规模化 (4周)
**Deadline**: 2026-07-31

| 目标 | 验收标准 |
|------|----------|
| 反馈闭环 | 用户反馈自动更新知识 |
| 分布式 | 存储层可切 Neo4j/pgvector |
| 企业级 | RBAC、审计、SLA |

## 技术指标

| 指标 | MVP | Phase 1 | Phase 2 |
|------|-----|---------|---------|
| 节点数 | 1K | 1M | 10M |
| 查询P99 | 1s | 200ms | 100ms |
| 规则数 | 10 | 100 | 1000 |
| 部署依赖 | 0 | 0 | 可选外部存储 |

## 非目标

明确不做，避免范围蔓延：

1. **通用 NLP 平台** —— 专注结构化知识，不做通用文本理解
2. **替代数据仓库** —— 不做 OLAP，专注实时规则推理
3. **可视化编排** —— Phase 2 前无拖拽式规则设计器
4. **多租户 SaaS** —— Phase 3 前不考虑租户隔离
