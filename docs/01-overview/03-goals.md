# 项目目标

## 阶段目标

### Phase 0: MVP (当前)
**Deadline**: 2026-04-30

| 目标 | 验收标准 |
|------|----------|
| Schema 可定义 | KGML YAML 解析通过 |
| 规则可执行 | 供应链金融5条规则跑通 |
| Demo 可演示 | 单脚本运行完整流程 |

### Phase 1: 可用 (4周)
**Deadline**: 2026-05-31

| 目标 | 验收标准 |
|------|----------|
| 查询高性能（分级目标） | 简单查询 P99 < 200ms / 图遍历 P99 < 2s / 混合检索 P99 < 1s |
| 规则热更新 | YAML 修改后秒级生效 |
| 本地图分析 | kuzu 嵌入图数据库接入，图遍历/路径查询/担保圈检测可用 |
| 本地管理面基础 | Space + Schema CRUD + 消费视图 API，配置驱动部署模式切换 |
| 平台化基础 | 审计 Schema 纳入存储表，DuckDB 本地持久化 |

> **本地优先选型说明**：Phase 1 完全基于本地存储（DuckDB + kuzu），不依赖任何外部服务。
> - DuckDB：实体存储、指标计算、审计日志、SQL 查询
> - kuzu（本地图数据库）：图遍历、路径查询、担保圈检测、循环检测
> - 两者通过统一 Repository 接口协同

### Phase 2: 好用 (4周)
**Deadline**: 2026-06-30

| 目标 | 验收标准 |
|------|----------|
| AI Native 能力 | MCP 协议支持，Claude Agent 可调，含管理面和消费面工具 |
| 可视化 | Schema/规则链/执行结果的 Web UI |
| 50W 节点支撑 | kuzu 优化，内存图索引，向量检索集成 |
| 多场景 | 3个垂直领域 Schema |

### Phase 3: 规模化 (4周)
**Deadline**: 2026-07-31

| 目标 | 验收标准 |
|------|----------|
| 反馈闭环 | 反馈自动触发影响分析+生成建议，人工确认执行 |
| 200W+ 节点支撑 | 分布式存储层可选（Neo4j/pgvector），可切换 |
| 企业级 | RBAC、审计、SLA |

## 技术指标

| 指标 | MVP | Phase 1 | Phase 2 | Phase 3 |
|------|-----|---------|---------|---------|
| 节点数 | 1K | 100K | 500K | 2M+ |
| 简单查询 P99 | 1s | 200ms | 100ms | 50ms |
| 图遍历 P99 | - | 2s | 1s | 500ms |
| 混合检索 P99 | - | 1s | 500ms | 300ms |
| 规则数 | 10 | 20 | 200 | 1000 |
| 部署依赖 | 0 | 0 | 0 | 可选外部存储 |

> **选型约束**：Phase 1-2 坚持零外部依赖，所有能力运行在单机本地。
> Phase 3 才引入可选的外部存储后端（DuckDB 保持为默认）。

## 非目标

明确不做，避免范围蔓延：

1. **通用 NLP 平台** —— 专注结构化知识，不做通用文本理解
2. **替代数据仓库** —— 不做 OLAP，专注实时规则推理
3. **可视化编排** —— Phase 2 前无拖拽式规则设计器
4. **多租户 SaaS** —— Phase 3 前不考虑租户隔离
