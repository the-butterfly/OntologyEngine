# API 设计指南

## 何时需要

新增以下任一情况，必须先写本文档：
- 新增 public 接口
- 修改现有接口签名
- 跨模块新增调用关系

## 模板

```markdown
# API 设计: {module}.{feature}

## 背景
{为什么需要}

## 接口

```python
class {Interface}:
    async def {method}(
        self,
        {param}: {type}  # 必填/选填
    ) -> {return_type}:
        \"{brief_doc}\"
```

## 输入

| 字段 | 类型 | 必填 | 约束 | 说明 |
|------|------|------|------|------|
| {name} | {type} | Y/N | {rule} | {desc} |

## 输出

| 字段 | 类型 | 说明 |
|------|------|------|
| {name} | {type} | {desc} |

## 异常

| 异常 | 场景 | 调用方处理 |
|------|------|------------|
| {Ex} | {when} | {how} |

## 示例

```python
result = await obj.method(param=value)
```

## 边界检查

- [ ] 不破坏现有接口
- [ ] 可被本地/远程实现
- [ ] 测试可覆盖
```

## 评审清单

| 检查项 | 标准 |
|--------|------|
| 必要性 | 是否已有类似接口？能否复用？ |
| 位置 | 是否放在正确层级？ |
| 依赖 | 是否引入新的跨层依赖？ |
| 命名 | 是否清晰、一致？ |
| 异常 | 是否定义完整异常层级？ |
