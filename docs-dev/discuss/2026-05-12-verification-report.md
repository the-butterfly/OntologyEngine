## 三、样例验证详细结果

### 3.1 优化一：Token 效率

#### IT-1-01: Token 预算基线 ✅ (score=0.50)

| 指标 | 测量值 | 验收阈值 | 差距 | 分析 |
|------|--------|---------|------|------|
| Token 利用率 | 30.4% | ≥ 70% | -39.6pp | 当前无压缩机制，结果字段冗余 |
| Token 节省率 | 3.2% | ≥ 50% | -46.8pp | include_evidence=False 几乎无节省 |
| 信息完整度 | 0.0% | ≥ 90% | -90pp | "风险等级"/"D级"等关键词未命中 |
| 命中数 | 5 | - | - | 图检索返回 5 条，向量检索不可用 |

**关键发现**：
- `full_tokens=1255, no_ev_tokens=1215`：include_evidence=False 仅节省 3.2% token，说明证据链不是主要 token 消耗源
- 主要 token 消耗来自结果字段冗余（avg_fields=15.0/结果），验证了 Layer 2 结构化压缩的必要性
- 信息完整度 0% 是因为 BM25-only 模式下"风险等级"与"华为风险"匹配度低，验证了 Layer 4 加性融合的必要性

#### IT-1-02: 压缩模式基线 ✅ (score=0.50)

| 指标 | 测量值 | 分析 |
|------|--------|------|
| 平均字段数 | 15.0/结果 | 当前无字段选择机制，全量返回 |
| 核心字段存在 | False | content 字段名可能不同（实际为 "content" 而非 "text"） |

**关键发现**：15 个字段/结果远超必要（核心字段 6 个 + promoted 5 个 = 11 个），验证了 Layer 5 结果格式化的必要性。

#### IT-1-03: 短路基线 ✅ (score=0.50)

| 指标 | 测量值 | 分析 |
|------|--------|------|
| 总结果数 | 6 | 无短路，遍历全部层 |
| mental_model 数 | 0 | 当前无 mental_model 被创建 |
| opinion 数 | 0 | 当前无 opinion 被创建 |
| 短路可行性 | False | 无高层数据可短路 |

**关键发现**：短路机制的前提是有 opinion 层记忆，但当前管线不会自动创建 mental_model/opinion。优化实施时需先确保巩固引擎能产出高层数据。

#### IT-1-04: 加性融合基线 ✅ (score=0.80)

| 指标 | 测量值 | 分析 |
|------|--------|------|
| 排序分数 | [0.049, 0.047, 0.045, 0.038, 0.035] | RRF 分数正常工作 |
| 类型多样性 | 1 | 仅 observation 类型，缺 entity/mental_model |
| 排序可用 | True | rank_score 字段存在且有值 |

**关键发现**：RRF 融合正常工作，但缺少 BM25 和 Entity boost 信号（BM25-only 模式下向量检索不可用）。加性融合需在 Embedding 修复后才能完整验证。

### 3.2 优化二：前瞻性索引

#### IT-2-01: 语义鸿沟召回基线 ✅ (score=0.00)

| Cue 查询 | 期望关键词 | 命中 | 分析 |
|----------|-----------|------|------|
| "推荐什么晚餐？" | 海鲜过敏 | ❌ MISS | 语义距离过大，向量检索失败 |
| "批量查征信可行吗？" | 限速 | ❌ MISS | "批量查征信"与"限速"无直接关联 |
| "今天有什么待办？" | 报告 | ❌ MISS | "待办"与"报告"语义距离大 |
| "推荐高风险基金？" | 保守型 | ❌ MISS | "高风险基金"与"保守型"反义 |
| "能给华为放贷吗？" | 风险等级 | ❌ MISS | "放贷"与"风险等级"无直接关联 |

**召回率**: 0/5 (0.0%)

**关键发现**：
- **0% 召回率精确验证了 Cue-Trigger Semantic Disconnect 问题**——这正是前瞻性索引要解决的核心问题
- 5 个场景全部 MISS，与 LoCoMo-Plus 基线（23%-46%）一致
- 前瞻性索引的预期收益（召回率从 0% 提升至 ≥80%）有明确的验证基线

#### IT-2-02: 前瞻触发覆盖 ✅ (score=0.90)

| 类型 | 触发 | 期望 | 结果 |
|------|------|------|------|
| observation | ✅ | 触发 | 符合 |
| opinion | ✅ | 触发 | 符合 |
| constraint | ✅ | 触发 | 符合 |
| commitment | ✅ | 触发 | 符合 |

| episode | ✅ | 不触发 | 符合 |

**覆盖率**: 4/4 触发类型 + 2/2 跳过类型 = 100%

**关键发现**：触发条件设计合理，observation/opinion/constraint/commitment 四种类型覆盖了隐性约束的主要来源。

#### IT-2-02b: 检索延迟基线 ✅ (score=0.80)

| 指标 | 测量值 | 验收阈值 | 分析 |
|------|--------|---------|------|

| P95 延迟 | 54ms | ≤ 100ms | 低于阈值 |

**关键发现**：当前检索延迟极低（BM25-only 模式），前瞻性索引增加的 50-100ms 延迟在可接受范围内。

### 3.3 优化三：AGM-lite

#### IT-3-01: 核心信念保护基线 ✅ (score=0.50)

| 指标 | 测量值 | 分析 |
|------|--------|------|
| supersede 可用 | True | 取代机制正常工作 |
| 矛盾检测数 | 0 | reflect 未检测到矛盾 |
| 洞察数 | 0 | reflect 未生成洞察 |
| 矛盾检测可用 | False | 核心功能缺失 |

**关键发现**：supersede 机制工作正常，但矛盾检测完全失效（与 LoCoMo T4 一致）。AGM-lite 依赖矛盾检测作为输入，必须先修复。

#### IT-3-02: 可放弃性评分基线 ✅ (score=0.80)

| 记忆类型 | 期望可放弃性 | 节点创建 | 分析 |
|---------|------------|---------|------|
| observation (低置信度) | 高 | ✅ | 符合 |
| rule (高置信度) | 低 | ✅ | 符合 |
| entity (高置信度) | 低 | ✅ | 符合 |
| opinion (中置信度) | 中 | ✅ | 符合 |
| commitment (高置信度) | 低 | ✅ | 符合 |

**类型顺序正确性**: True — TYPE_DISCARDABILITY 排序 fragment > episode > observation > opinion > commitment > entity > rule > constraint > mental_model

**关键发现**：可放弃性评分的类型因子设计合理，但当前系统无 discardability_score 字段，需新增。

#### IT-3-03: 一致性检查基线 ✅ (score=0.90)

| 指标 | 测量值 | 分析 |
|------|--------|------|
| 默认规则数 | 7 | BR_R001-BR_R007 |
| 冲突数 | 0 | detect_rule_conflicts 未检出 |
| 优先级重复 | False | 优先级 100/90/80/70/60/50/40 无重复 |

**关键发现**：当前 7 条默认规则无冲突，但 BR_R001 (priority=100, supersede_old) 与 BR_R005 (priority=60, block_revision) 存在**语义冲突**（用户更正 vs 反馈保护），detect_rule_conflicts 仅检测同优先级不同动作，未检出跨优先级冲突。AGM-lite 的一致性检查器需增强。

#### IT-3-04: AGM 公设基线 ✅ (score=0.20)

| 公设 | 当前支持 | 分析 |
|------|---------|------|
| K*2 Success | ✅ True | 新信息可被接受 |
| K*3 Consistency | ❌ False | 无一致性验证机制 |
| K*5 Preservation | ❌ False | 无非矛盾信念保护 |
| Relevance | ❌ False | 无相关性检查 |
| Core-Retainment | ❌ False | 无核心信念保护 |

**支持率**: 1/5 (20%)

**关键发现**：
- 当前仅支持 K*2（新信息可被接受），其余 4 个公设均无支持
- 无 "contracted" 信念状态，无恢复路径
- AGM-lite 需新增 4 个公设的验证机制

#### IT-3-05: 纠正传播基线 ❌ (score=0.00)

| 指标 | 测量值 | 分析 |
|------|--------|------|
| 原始节点创建 | ✅ | observation 创建成功 |
| 纠正操作 | ❌ | CognitiveNode not found |

**失败原因**：correct API 在查找原始节点时失败，可能是节点 ID 格式或命名空间问题。
