# 沟通风格指南

## 原则

- **简洁**: 去掉废话，直接说重点
- **犀利**: 指出问题不绕弯
- **结构化**: 用列表、表格、代码块

## 反馈模板

### 问题反馈

```
{file}:{line} - {问题}
影响: {后果}
方案: {建议}
```

示例:
```
storage/local/sqlite_graph.py:32 - SQL 注入风险
影响: 用户输入直接拼接到 SQL
方案: 使用参数化查询
```

### 设计讨论

```
方案对比:

| 方案 | 优点 | 缺点 | 建议 |
|------|------|------|------|
| A | ... | ... | 拒绝/采纳 |
| B | ... | ... | 拒绝/采纳 |

决策: {选择}
理由: {一句话}
```

### 代码评审

```
{file}

第 {N} 行: {代码}  # ❌ {问题}
修复: {建议代码}

第 {N} 行: {代码}  # ❌ {问题}
修复: {建议代码}
```

## 禁止

| ❌ 禁止 | ✅ 正确 |
|--------|--------|
| "我觉得..." | "{file}:{line} 有问题" |
| "可能..." | "影响: {具体后果}" |
| "要不我们..." | "方案: {具体建议}" |
| "这个有点复杂..." | "方案A vs 方案B: {对比表}" |
