# 技术栈选型

> **状态**: 设计中  
> **级别**: L0 - 架构层  
> **目标读者**: 架构师、技术负责人

## 选型原则

1. **成熟稳定**: 优先选择经过生产验证的技术
2. **生态丰富**: 活跃的社区和完善的文档
3. **性能优先**: 满足性能指标要求
4. **云原生**: 支持容器化和弹性扩展
5. **开源优先**: 降低许可成本，避免供应商锁定

## 存储技术选型

### 图数据库

| 选项 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **Neo4j** | 成熟、文档丰富、Cypher 标准 | 企业版收费 | 通用场景 |
| **TuGraph** | 高性能、开源、国产 | 生态较小 | 大规模图 |
| **NebulaGraph** | 分布式、云原生 | 运维复杂 | 超大规模 |

**推荐**: Phase 1 使用 Neo4j Community，Phase 2 评估 TuGraph

### 向量数据库

| 选项 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **pgvector** | 与 PostgreSQL 集成、简单 | 性能一般 | 中小规模 |
| **Milvus** | 专业向量库、高性能 | 独立部署 | 大规模 |
| **Qdrant** | Rust 实现、性能优秀 | 较新 | 云原生 |

**推荐**: 使用 pgvector (已集成 PostgreSQL) 或 Qdrant

### 关系型数据库

| 选项 | 用途 |
|------|------|
| **PostgreSQL** | 主数据库、元数据存储、向量扩展 |
| **Redis** | 缓存、会话、分布式锁 |
| **ClickHouse** | 时序数据、分析查询 (可选) |
